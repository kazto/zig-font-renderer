# User Stories

## Feature: Font Parsing (Pure Zig)

### US-1: TrueType/OpenTypeファイルの解析
- **As a**: 開発者 (ケンジ)
- **I want to**: TTF/OTFファイルを読み込んで、内部のグリフデータやテーブルにアクセスしたい
- **So that**: レンダリングやシェイピングに必要な情報を取得できる
- **Acceptance Criteria**:
  - [ ] 外部Cライブラリを使用せず、Pure Zigでパースできること
  - [ ] `head`, `hhea`, `maxp`, `cmap`, `glyf` (または `CFF `), `hmtx` 等の主要テーブルが読み込めること
  - [ ] 無効なフォントファイルに対して適切なエラーを返すこと

## Feature: Text Shaping (Advanced)

### US-2: ラテン文字と日本語の基本シェイピング
- **As a**: 開発者 (ケンジ) / CLIユーザー (ユミ)
- **I want to**: 指定したテキストを、フォントのメトリクスに従って正しく配置したい
- **So that**: 文字の間隔（アドバンス幅）が正確に保たれたレンダリング結果が得られる
- **Acceptance Criteria**:
  - [ ] 各文字（Unicode）を対応するグリフインデックスに変換できること
  - [ ] グリフごとのアドバンス幅を考慮して水平配置ができること
  - [ ] 漢字、かな、ラテン文字が混在しても正しく配置されること

### US-3: カーニングと合字のサポート
- **As a**: 開発者 (ケンジ)
- **I want to**: `GPOS` と `GSUB` テーブルを利用した高度なシェイピングを行いたい
- **So that**: プロフェッショナルなタイポグラフィ（カーニング、合字）を実現できる
- **Acceptance Criteria**:
  - [ ] `GPOS` テーブルによるペアカーニングが適用されること
  - [ ] `GSUB` テーブルによる合字（例: "fi"）の置換が適用されること
  - [ ] HarfBuzzの結果と（この範囲において）同等の出力を得られること

## Feature: SVG Rendering

### US-4: テキストのアウトライン出力 (SVG Path)
- **As a**: CLIユーザー (ユミ)
- **I want to**: テキストをSVGの `<path>` 要素として出力したい
- **So that**: フォントがインストールされていない環境でも正しく表示され、デザインツールで加工できる
- **Acceptance Criteria**:
  - [ ] グリフのアウトライン（ベジェ曲線、直線）をSVGの `d` 属性に変換できること
  - [ ] 1つのSVGファイルに、シェイピングされた全テキストが含まれること
  - [ ] 座標系が反転せず、正しく表示されること

## Feature: CLI & Library API

### US-5: CLIインターフェースの提供
- **As a**: CLIユーザー (ユミ)
- **I want to**: コマンドラインからフォント、テキスト、出力先を指定して実行したい
- **So that**: 他のツールやスクリプトから簡単にフォントレンダリングを利用できる
- **Acceptance Criteria**:
  - [ ] `--font`, `--text`, `--output` (または位置引数) で操作できること
  - [ ] 成功時には何も出力せず、エラー時にはstderrに分かりやすいメッセージを出すこと
  - [ ] 終了コードが適切であること（成功時0、エラー時非0）

### US-6: デュアルAPI（高レベル・低レベル）の提供
- **As a**: 開発者 (ケンジ)
- **I want to**: 用途に応じて、簡潔なAPIと詳細なAPIを使い分けたい
- **So that**: 実装コストの削減と、細かい制御の両立ができる
- **Acceptance Criteria**:
  - [ ] 高レベルAPI: `renderToSvg(allocator, font_path, text)` のような形式で動作すること
  - [ ] 低レベルAPI: 各テーブルデータや生のアウトラインポイントにアクセス可能であること
